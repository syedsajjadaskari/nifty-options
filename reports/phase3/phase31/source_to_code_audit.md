# Phase 3.1 - independent source-to-code audit

**Scope.** Every entry condition of IRF, ORB, PDR, PDS and RF compared with the original PDFs in `docs/strategy_docs/`. Two auditors worked in parallel on the repository **read-only**; each first rendered and read the PDF pages (text and charts) and wrote down the source evidence **before** opening any code or any earlier AI-written document (Part A of each report), then compared the code (Part B / Parts 2-3). A passing unit test was never accepted as evidence that a rule is source-verified: a test proves only that the code does what the test author thought the source says.

**Status vocabulary.** `SOURCE_VERIFIED` (the PDF states it explicitly and the code matches), `USER_APPROVED` (owner-approved research or execution rule, not in the PDF), `PROPOSED_FOR_REVIEW` (a stand-in the code needs, not approved), `UNRESOLVED` (the source is silent, conflicting or not numeric). Code-vs-source: `EQUIVALENT`, `STRICTER`, `LOOSER`, `DIFFERENT`, or "qualitative: cannot tell".

**Reading the two reports.** They are reproduced unedited as Appendix A (IRF, RF) and Appendix B (ORB, PDR, PDS) below. Line numbers refer to the code as audited; the D-IRF-1 fix of this phase (`irf.py`, see `confirmed_software_defects.md`) shifted a few IRF lines by up to 4. Counts in the appendices are counts of engine output (no exits, no profit). Some figures use the Phase 3.0 baseline configuration, others the shipped defaults; each table says which.

## Where the code is STRICTER, LOOSER or DIFFERENT than the source (headline items)

* **Looser than any human reading:** IRF all-day re-arming, no expiry, M2B single-candle push, E1 extension, K1 fractal as "support"; PDR zone on every gap-up day and green-after-touch with no hold test; PDS Method 3 support unbounded below the zone; ORB "excessively extended" gap not excluded (no number in the document).
* **Stricter than the source:** IRF Method 3 (0 signals: pivot lag, exact 60-70% band, no alternate "higher price rejection" trigger); IRF Method 1 limited to the very next candle (contradicted by the p.14 card and Reference Chart 2); RF trend filter; ORB candle-quality and trend; ORB gap setup requires the open already beyond the MA (the figures show the open on the old side).
* **Different:** fixed 35-point stop versus the guides' "35 or 40 by the recent opposite candle"; the T1/two-leg/post-T1-stop exit (owner-approved); RF reference price = close of the return candle (guide: "OPEN").

## Unresolved source conflicts recorded (not decided here)

IRF Method 1 "very next candle" (pp.5/6/13) versus "next or following" (p.14) and Reference Chart 2 (fails on the 4th candle); IRF p.14 stop text garbled; IRF Method 3 alternate trigger undefined; ORB gap setup text ("the gap pushes price through the 200 DMA") versus figures p.8/9; ORB units of 30/60 declared undefined by the document; PDR zone: charts 1-2 "day's high candle", chart 3 "shelf"; PDR/PDS stop 35 versus 40 selection (PDS gives a distance rule, PDR none); PDS Method 3 "near" and size undefined; RF direction, target, entry price and "return inside" not stated.

### Causality audit (definitions.py, irf.py, rf.py)
- pivot_lows/pivot_highs (definitions.py:156-162): j in range(max(lo,k), i-k) => j <= i-k-1, so the last candle read is j+k <= i-1. Candle i (the signal candle) is never a neighbour of a pivot. No off-by-one. Consequence (a lag, not a leak): a pivot at i-1 can never be "recent support", and one at i-2 only if candle i-1's low is >= it.
- confirmed_swing_highs/lows (166-176): j in range(max(lo,k), upto-k+1) => j <= upto-k, confirmed by candle j+k <= upto. Correct. structure_trend (333-363) calls it with len(cs)-1 on the PREVIOUS session only, so it cannot use today's candles.
- recent_support (180-192) docstring "known BEFORE candle i" matches the arithmetic; recent_resistance (196-201) the same (pivot_highs(cs,b,i,1) => j<=i-2).
- IRF M2B `pushed` uses cs[m].h for m up to i inclusive (irf.py:150) - candle i is the just-closed signal candle, so causal (and it is the interpretive choice discussed below).
- EMA: ema200_5m is a causal column (sessions.causal_ema); trend_check for the default modes uses previous-session data only.
- EMPIRICAL look-ahead test (read-only): for every one of 247 sessions and every prefix k=2..N candles I ran evaluate_session(ctx.prefix(k)) and compared the CONFIRMED records stamped at candle k's bar_end with the full-session run. 18,278 comparisons per configuration; configurations: IRF default, IRF variant (m1 window 3, SWING_K2, MIN_60), RF with EMA5M_BASIC. MISMATCHES = 0 in all three. The prefix property means no decision at candle k depends on candles after k. (RF default trend_mode uses only previous-session data, so it is covered by the same argument; it was not separately prefix-tested.)
- Verdict: no look-ahead found in the swing helpers or in the IRF/RF engines.

### 3C. Direct answers

**(a) Why the engine emits far more IRF signals than a human**
Measured with default ProposalConfig over 247 sessions: 874 confirmed signals = Method 1 349, Method 2A 215, Method 2B 310, Method 3 0. 174 sessions have >=1; only 9 sessions have exactly 1; 165 sessions have >1 (histogram signals/day: 1:9, 2:29, 3:24, 4:22, 5:18, 6:26, 7:10, 8:15, 9:10, 10:4, 11:4, 12:2, 13:1). Mean 5.0 per signalling day. After 13:00: 325 at bar_end >= 13:00 (317 strictly after), i.e. 37.2% (M1 30.1%, M2A 41.4%, M2B 42.3%).
Mechanical reasons, each tied to code and a number:
1. No "first breakout only" rule; IRH is a static level all day and the engine re-arms on every upward close-cross (irf.py:77-80, 69). 176 of 247 sessions close above IRH at least once; mean 1.85 upward crossings per session, max 8. Only 176 of the 874 signals belong to the session's FIRST close above IRH (M1 44, M2A 63, M2B 69); 698 come from later crossings.
2. Re-arming inside the same candle: in 440 of the 525 Method-2 signals the trigger candle itself closes above IRH, so it immediately becomes the breakout candle of a NEW attempt (irf.py:75 then 77). One long grind above IRH can therefore produce a chain of M2A/M2B signals.
3. No expiry on Method 2 (IRF-M2-006 UNRESOLVED; params.py:136 None): median breakout-to-trigger 10 / 8 candles, 120 + 114 signals fire >=10 candles after the breakout, max 49 / 58 candles. A 6-candle expiry would cut M2A 215->84 and M2B 310->211.
4. No "price holds above IRH" check for Method 2 despite p.13: 62/215 M2A and 49/310 M2B had already closed back <= IRH between the breakout and the trigger; 69/215 M2A and 15/310 M2B trigger with the close below IRH (M2A 7 below IRL); 51/215 M2A supports sit below IRH.
5. Low-bar proposals: E1 extension (one tick above the breakout candle), support = any latest 3-candle fractal low (LAST_N3 would be 309), any red candle, M2B single-candle push (63/310). E2 extension would give M2A 334.
6. No time window: 37.2% of signals are at/after 13:00 and 104 sessions have their first signal by 10:30 while the later ones are still counted (signal_window_end=None, params.py:181). Restricting to bar_end<=10:30 leaves 186 signals in 104 sessions; <=13:00 leaves 557 in 152 sessions.
7. Three independent engines (M1, M2A, M2B; M3 is silent) run in parallel; 64 candles carry more than one record (130 records). IRF-GLOBAL-005 keeps them as separate records, so any consumer that counts records double-counts.
8. A max_signals_per_session=1 exists but is NOT applied to IRF (params.py:178; irf.py has no cap).
What is NOT a driver: the Method 1 "very next candle" choice (+3 only) and Method 3 (zero).
The guide itself never states trades per day, a latest entry time, re-arming or expiry (checked all 17 pages), so these are unresolved by the source, not violated by the code.

**(b) Which RF condition removes most setups**
Funnel on 247 sessions (1 has no usable previous session): gap not up 106 -> gap up 140 -> open within yesterday's range 80 (60 removed) -> close below RF Low 51 (29 removed) -> return inside (R1) 36 (15 removed) -> trend filter STRUCTURE_EMA_SWING2 leaves 2 (34 of 36 removed = 94%). With EMA_PREV_SESSION_CLOSE 12 remain; with EMA5M_BASIC 20 remain; R3 (next candle only) with the default trend: 1; R2 touch: 2.
Engine's own tally (it applies the trend FIRST because the text does): 180 RF records: 141 sequences complete; of them 67 'previous close on the wrong side of EMA(200)', 49 'swing structure not HH/HL', 12 'GAP_NOT_UP', 11 'GAP_UP_OUTSIDE_YESTERDAYS_RANGE', 2 CONFIRMED; plus 38 'no return inside before session end' and 1 NOT_EVALUATED. So the single dominant remover is the PROPOSED trend filter, not any condition written in the RF guide. Among source-written conditions the largest are 'gap not up' (106) then 'gap beyond yesterday's high' (60). Under the literal source conditions without any numeric trend proxy (gap up, in range, close below, return inside) there are 36 sessions/yr; the journal's 17 RF trades is the same order of magnitude, the default engine's 2 is not (the 5 in the backtest was not reproduced: I get 2 with the defaults).

**(c) Does the RF figure set support "long only"?**
Yes, indirectly, and nothing contradicts it. The text never says long. Evidence: p.2 "the opposite of the IRF strategy" (IRF is short only), p.1 "UPTREND ONLY", Fig 2 (dip below the first candle then recovery inside the range in an uptrend), and p.9 'Ref. images': all three screenshots use the TradingView long-position box (profit zone above entry, stop zone below entry); image 2 shows Stop 40.65 / Target 60.80 / R:R 1.5 / Closed P&L -40.65 (a stopped-out long). ### ORB Rulebook (ORB_Strategy_Rulebook-2.pdf, 13 pp; pages are Letter, figures are NOT numbered; I number them below)
Text (p1): "The decision is made at 9:20 AM, once the first 5-minute candle has closed, and the same rules apply in both directions"; "9:20 | 30 | 60 | 1:2" (decision time, stop-loss, target, RR).
p1 table: Method 1 = "Previous day's resistance (long) / support (short)", trend "Established trend in trade direction", gap "Not mandatory". Method 2 = "Inner resistance / support inside the previous day's range, with a trendline", trend "Established trend in trade direction", gap "Not mandatory". "Gap + 200 DMA": level "200 DMA", trend "Not mandatory if conditions qualify", gap "Required (up for long, down for short)".
p2: "Strong bullish candle; limited upper-wick rejection" / "Strong bearish candle; limited lower-wick rejection". "The correct level, the first candle's closing price, the 200 DMA filter (where applicable) and the absence of strong rejection wicks decide whether a setup qualifies."
p2-3 "At 9:20 AM: 1. Identify the previous day's resistance / support. 2. Check the overall trend and the position of the 200 DMA / EMA on your chart. 3. Evaluate the candle's body, upper wick and lower wick. 4. Confirm whether price has broken (and closed beyond) the relevant level." p3: "The candle's final shape and closing price are unknown before 9:20 AM. Never pre-empt the close."
p3 Method 1 long: "Confirm the uptrend. Price above the 200 EMA is a basic confirmation, supported by bullish price structure. 2. Mark previous-day resistance with a horizontal line. 3. ... It must break above and close above the level, with a strong green body and a small upper wick. 4. Enter long at 9:20 AM". p4 short: mirror, "strong red body and a small lower wick".
p4 Method 2: "Method 2 is used when the market is trending but price has not broken the major previous-day level. That major resistance sits outside - at the top of the previous day's range. Inside the previous day's range there is usually a smaller resistance (a minor swing high or consolidation top). The break of that inner resistance - in an uptrend, near the rising trendline - is a valid ORB entry at 9:20 AM, even before the major resistance is broken." Table: "Major level (outside): Top of the previous day's range (resistance) / bottom (support)"; "Inner level (inside): A smaller level within the previous day's range"; "Needs the trendline? Method 1: No; Method 2: Yes".
p5 steps: "Draw the rising trendline through the relevant swing lows ... Mark the inner resistance ... check that the first candle breaks and closes above the inner resistance ... convincing green body, limited upper wick ... Apply the 200 EMA filter - if the breakout is near the EMA, wait for a convincing close above it."
p7 "A trendline by itself is not an entry signal. The inner-level breakout and the candle confirmation are still required. Verify the exact levels and first-candle close on your original chart."
p7-9 Gap setup: "Unlike Methods 1 and 2, it can be considered even when the market was previously trending the other way - provided the gap pushes price through the 200 DMA and the first 5-minute candle closes beyond it." p8: "Identify the gap up - the market opens above the previous close. (No number for 'excessively extended'.)
p10 candle quality (figure: long view): "Preferred: Large green body, close near the high, small upper wick, clear break of level / DMA"; "Conditional: Bullish pin bar - rejection of lower prices; its position and close must support the breakout"; "Reject: Strong upper-wick rejection". p11: "Entry: 9:20 AM, after the first-candle close; Stop-loss Entry - 30; Target Entry + 60"; "Standardize your units: Decide and write down whether 30 and 60 mean index points, instrument price units, or rupee P&L." ## B4. Causality
- Previous-session-only inputs: pdr_zone/pds_zone/prev_high_low/trend_check/inner level/trendline read only ctx.previous (definitions.py:392-401, 316-363; orb.py:140-151); the swing helpers confirm a swing only when its k later candles are closed (definitions.py:156-176: j <= upto-k).
- 5m EMA is causal (sessions.py:294-308: seeded SMA, each value uses data up to its position) and runs across sessions on concatenated 5m closes with a warm-up file; candle 0's EMA includes candle 0's close, which is known at 09:20. open_price is the 09:15 open. The official previous close (daily vendor close) is known before today's open.
- Intra-session loops (pdr.py:79-107, pds.py:69-115) read candle i and earlier only; Method-3 support uses pivot_lows(cs,start,i,1) with j <= i-2.
- Empirical test I ran: for ORB, PDR and PDS, under both the default and the phase-3 baseline configs, for every session and prefix lengths 1,2,3,8,20,45,70 candles (10,374 comparisons): the set of CONFIRMED signals with timestamp <= the prefix end is IDENTICAL when the session context is truncated (ctx.prefix(n)). 0 mismatches. So no lookahead in signal generation.
- Minor non-causality-related caveat: signals stamped 15:30 are the 15:25 candle in closing-auction regime days; selection.py blocks them from entry (is_valid / classify_bar), but they appear in raw counts (21 in the 383 raw PDR signals).

## B5. Implementation defects vs interpretation choices
IMPLEMENTATION DEFECTS (explicit source wording contradicted): only one that I can support with explicit wording.
D1. PDS Method 3 "near the zone" has no lower bound. Source p5: "Wait for price to build a small support near the zone, then take the short when that support breaks" (also fig3 Method 3: support sits just under the zone). Code pds.py:125: `js = [j for j in pivot_lows(cs, start, i, 1) if cs[j].l <= near_ceiling]` with near_ceiling = zone.high + prox (pds.py:103): any k=1 fractal low anywhere below the zone qualifies. Failing input: session 2026-07-23, M3 signal at 13:05 with small_support 23,843.45 vs zone_low 23,961.60 (118.1 pts below the zone). Minimal fix: also require the support candle to be at the zone, e.g. in _small_support add `and at_zone(cs[j])` / `cs[j].h >= zone.low - prox`, or a lower bound `cs[j].l >= zone.low - tol`; tol is a new parameter that would need approval. (Whether "near" is a defect or an unresolved number is arguable: the guide lists the size of the small support as undefined, but not its distance; so I class it as a defect against "near the zone".)
No other code line contradicts explicit wording. Items that look like defects but are interpretation or documented omissions:

INTERPRETATION / DOCUMENTED-OMISSION DIFFERENCES (not defects)
I1. ORB trend uses PREVIOUS session close vs EMA (and variant B swing structure) instead of "Price above the 200 EMA" now (O6): stricter; owner-approved variants. 
I2. ORB gap setup requires the open beyond the MA, figures p8/p9 show the open on the old side (O10): stricter; 10 events.
I3. ORB "excessively extended" gap filter not applied (O11): explicitly flagged unresolved, looser.
I4. ORB M2 inner level/trendline are inventions (O4-O5): the source gives none; the coded level is broken in 79% of sessions so it adds a lot of potential (but trend/trendline/quality cut M2 to 16 records).
I5. PDR zone = latest swing high with a red candle, not the day's high (P1), open above zone (P4), any later green (P6), reversal filter off (P7): see B2. P6 is the closest to a source contradiction (the sequence says "Support test", but entries occur after the zone failed: 26 of 61 first signals close below the zone floor; example 2025-09-02: with the cap lifted a second PDR long fires at 14:10 close 24,564.60, 70 points under the zone [24,632.25, 24,635.00]). I did not call it a defect because no sentence says the zone must hold.
I6. PDR/PDS asymmetric zone construction (B for PDR, A for PDS) and PDR ZONE_WICK vs PDS ZONE_FULL (params.py:146,150).
I7. ORB/PDR/PDS `max_signals_per_session` lifted to 99 in the baseline: PDR emits 383 raw signals; the controller (not the engine) limits entries, so counts of "signals" and "trades" differ.
